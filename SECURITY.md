# Security Policy

## Supported versions

Security fixes are applied to the latest release and the `main` branch.

## Reporting a vulnerability

Please do not open a public GitHub issue for a suspected vulnerability, and do not include passwords, tokens, API keys, personal data, or other secrets in a report.

Instead, use GitHub's private vulnerability reporting feature from this repository's **Security** tab and select **Report a vulnerability**. This keeps the report visible only to the maintainers while it is assessed.

If **Report a vulnerability** is unavailable, do not disclose vulnerability details publicly. Open a minimal public issue asking the maintainers for a private contact method instead.

Please include:

- A clear description of the vulnerability and its potential impact
- The affected component, version, commit, or branch
- Reproduction steps or a minimal proof of concept
- Any relevant logs, screenshots, or links, with secrets removed
- Suggested mitigations, if known

We aim to acknowledge private reports within five business days. Further updates and any remediation timeline will depend on the severity, reproducibility, and scope of the issue.
